# ⚖️ ПравоКейс
### Автоматизированная система управления юридическими проектами и корпоративными знаниями

**Учебный проект по дисциплине «Информационный менеджмент»**

Техническое задание на создание автоматизированной системы по ГОСТ 34.

---

## 📌 О проекте

**ПравоКейс** — концепция автоматизированной информационной системы для юридической компании, оказывающей правовую поддержку крупному и среднему бизнесу.

Система призвана решить проблемы разрозненного хранения информации, повторного сбора данных у заказчиков и недостаточного использования профессионального опыта, накопленного сотрудниками в ходе предыдущих проектов.

Главная идея — создать единую цифровую среду, объединяющую информацию о клиентах, юридических проектах, сотрудниках, документах и профессиональных знаниях компании.

**Результат проекта:** техническое задание, определяющее функциональные, технические, организационные и эксплуатационные требования к будущей системе.

---

## 🎯 Цели проекта

Разработать техническое задание на создание АС «ПравоКейс», которая позволит:

- Централизованно хранить информацию о заказчиках и проектах.
- Повторно использовать накопленный юридический опыт.
- Быстро находить необходимые документы и правовые материалы.
- Координировать работу проектных команд.
- Контролировать сроки, задачи и ответственность сотрудников.
- Исключить повторный сбор уже имеющейся информации у заказчиков.
- Повысить эффективность проектной деятельности компании.

---

## 💡 Функциональные возможности системы

Система будет состоять из шести основных подсистем.

**👥 1. CRM и управление клиентами**

- Единая база заказчиков.
- Хранение контактных данных и реквизитов.
- История взаимодействия с клиентами.
- Связь заказчиков со всеми реализованными проектами.

**📁 2. Управление проектами**

- Создание и настройка юридических проектов.
- Назначение руководителей и исполнителей.
- Распределение задач между специалистами.
- Контроль сроков и этапов выполнения.
- Отслеживание статусов проектов.

**🧠 3. Корпоративная база знаний**

- Хранение юридических кейсов.
- Каталогизация судебной и правовой практики.
- Сохранение экспертных заключений.
- Поиск решений по тематике и отрасли.
- Повторное использование опыта предыдущих проектов.

**📄 4. Электронный документооборот**

- Централизованное хранение документов.
- Привязка файлов к клиентам и проектам.
- Версионность документов.
- Поиск по названиям, категориям и содержанию.
- Управление доступом к материалам.

**🔐 5. Информационная безопасность**

- Авторизация пользователей.
- Разграничение прав доступа.
- Защита клиентской информации.
- Журналирование действий пользователей.
- Резервное копирование данных.

**📊 6. Аналитика и отчётность**

- Контроль текущих и завершённых проектов.
- Анализ загруженности сотрудников.
- Отчёты по срокам и результатам.
- Мониторинг эффективности проектной деятельности.

## 🏗️ Архитектура системы

АС «ПравоКейс» проектируется по модульному принципу. Все функциональные подсистемы взаимодействуют с единой информационной базой.

**Основная логика работы:**

```text
          ЗАКАЗЧИК
              |
              ▼
        ЕДИНАЯ CRM
              |
              ▼
       ЮРИДИЧЕСКИЕ
          ПРОЕКТЫ
              |
       ┌──────┴──────┐
       ▼             ▼
  СОТРУДНИКИ     ДОКУМЕНТЫ
       |             |
       └──────┬──────┘
              ▼
       КОРПОРАТИВНАЯ
        БАЗА ЗНАНИЙ
              |
              ▼
      ПОВТОРНОЕ ИСПОЛЬЗОВАНИЕ
        НАКОПЛЕННОГО ОПЫТА
```

История заказчика и результаты предыдущих проектов будут доступны уполномоченным сотрудникам независимо от изменения состава проектной команды.

## 🔄 Организация командной работы

Для управления проектом используются GitHub Issues и GitHub Projects.

Каждый участник получает индивидуальные задачи, отвечает за подготовку закреплённых разделов и участвует во взаимной проверке.

**Жизненный цикл задачи:**

`Backlog` → `In Progress` → `Review` → `Rework` → `Done`

1. Руководитель распределяет задачи.
2. Участник разрабатывает свой раздел.
3. После завершения задача передаётся на проверку.
4. Проверяющий оставляет замечания.
5. Автор исправляет выявленные недостатки.
6. После согласования задача закрывается.

## 📅 Этапы реализации проекта

1. **Планирование** — формирование команды, распределение ролей и создание GitHub.
2. **Анализ** — изучение кейса, выявление проблем и определение целей автоматизации.
3. **Проектирование** — разработка концепции и функциональной архитектуры.
4. **Подготовка ТЗ** — написание индивидуальных разделов.
5. **Проверка** — взаимная вычитка и устранение противоречий.
6. **Сборка** — объединение разделов в единый документ.
7. **Финализация** — подготовка отчёта и размещение материалов в LMS.
8. **Защита** — демонстрация технического задания на вебинаре.
